# MOE-ptimizer — LLM project map

A concise, structured map of the MOE-ptimizer repository for LLMs and coding agents.
Read this first when asked to navigate, modify, or extend the codebase.

## One-paragraph summary

MOE-ptimizer is a transparent OpenAI-compatible input-context proxy for long-running
agentic workloads on MoE + MTP models. It addresses growing multi-turn transcripts:
verbatim replay raises prefill/TTFT, while careless compaction breaks prefix reuse or
loses task/code state. It preserves byte-stable prefixes, compacts only the request
context, and passes the backend-generated response through unchanged. It optimizes
the accumulated conversation as a whole rather than treating each prompt in
isolation. It does NOT compress response verbosity or generate responses.

## Key facts

- **Language / runtime**: Python 3.11+ (also 3.12). FastAPI + uvicorn,
  pydantic-settings, tree-sitter, LanceDB, tiktoken, numpy.
- **Version**: `0.7.27` (source of truth: `pyproject.toml`; kept in sync with
  `src/moeptimizer/__init__.__version__`).
- **Package**: `src/moeptimizer/`. Entry point `python -m moeptimizer` (console script
  `moeptimizer`). Config validator: `moeptimizer-config-check` / `--check-config`.
- **Ports**: proxy `:8080` (start via `bash scripts/run.sh`); backend `:13305`
  (`MOEPT_SERVER__URL`, default `http://localhost:13305/api/v1`).
- **Config**: environment variables with `MOEPT_` prefix and `__` nesting, e.g.
  `MOEPT_AGENTIC__QUALITY_PROFILE` (one of `quality` / `balanced` / `aggressive`),
  `MOEPT_AGENTIC__MAX_OPTIMIZED_TOKENS`, `MOEPT_V050__CACHE_STABLE_MODE`,
  `MOEPT_V050__FOLD_WINDOW_FRACTION` (space-based folding, default 0.25 = on). Copy
  `.env.example` to `.env`.
- **Endpoints**: `POST /v1/chat/completions`, `POST /v1/embeddings`, `GET /v1/models`,
  `GET /v1/health`, `POST /v1/agent/state`, `POST /v1/agent/state/reset`,
  `GET /v1/agent/sessions`, `GET /v1/agent/sessions/{id}/debug`,
  `GET /v1/agent/sessions/{id}/content/{handle}`, `DELETE /v1/agent/session/{id}`,
  `POST /v1/cache/clear`, `POST /v1/config/reload`, `GET /v1/metrics`,
  `POST /v1/metrics/reset`, `GET /v1/metrics/ui`, `GET /v1/debug/requests`
  (bounded per-request trace: prompt hash, slot, prompt/cache/fresh-prefill tokens,
  TTFT — no prompt contents by default).
- **Core modules**: `app.py` (FastAPI + streaming), `optimizer.py` (main pipeline),
  `config.py` (settings), `budget_governor.py` (budget math, extracted from optimizer),
  `session_manager.py`, `compactor.py`, `token_aware_truncator.py`, `token_counter.py`,
  `tool_output_compressor.py` / `tool_output_filter.py` (error-aware tool compression),
  `content_store.py` (reversible-compression handles + `expand_content`),
  `code_chunking.py` / `code_block_optimizer.py`, `state_rag.py`,
  `hierarchical_summarizer.py`, `backend_client.py`, `backend_capabilities.py`.
- **Tests**: `pytest tests/` (`asyncio_mode = "auto"`), one `test_<module>.py` per
  module. Integration tests: `test_e2e.py`, `test_optimizer.py`. Fixtures in
  `tests/conftest.py`.
- **Lint / types**: `ruff check src/ tests/`; `mypy --strict src/moeptimizer/`.
  Full suite: `bash scripts/dev.sh`.
- **Benchmark**: `python benchmark/benchmark.py` compares direct vs proxy (agentic
  OpenCode-harness by default). Scenarios: `debug`, `refactor`, `feature`, `default`,
  `*_long` variants, `opencode`/`fixtures`. Flags: `--turns`, `--rounds` (default 5),
  `--profile`, `--min-similarity` (regression gate, exit 2), `--json`, `--no-agentic`,
  `--no-measure-ttft`. Report UI: `benchmark/dashboard.html`.

The tagged 30-turn `cachefix_30turn` replay is summarized in the README's
Benchmark evidence table. It reported 49.01% prompt-token savings, 35.6% lower
mean latency, 46.9% lower mean TTFT, 94.23% proxy cache reuse, and 71.8% lower
fresh prefill in one round. It also reported three code-block-loss turns and
mean semantic similarity of 0.1956; treat it as a performance signal, not
response-quality sign-off.

## Pipeline stages (src/moeptimizer/optimizer.py)

`AgentContextOptimizer` orchestrates one module per stage. The main stages:

- **Session management** — `session_manager.py` (per-session isolation + stable
  anonymous session resolver).
- **Scratchpad compaction** — `compactor.py` (front-loading eviction for MTP
  protection).
- **Thinking preservation** — `thinking_preserver.py` (protects recent `<think>`
  blocks, archives stale reasoning).
- **State-based RAG** — `state_rag.py` + `state_store.py` (graph-indexed retrieval:
  Goal → Subtask → Tool → Outcome) + `symbol_index.py` (fuzzy symbol lookup).
- **Loop detection** — `loop_detector.py` (repeated tool calls / actions / thinking).
- **Progress tracking** — `progress_tracker.py` + `goal_decomposer.py`.
- **Code chunking** — `code_chunking.py` (tree-sitter-aware splitting + language
  detection) + `code_block_optimizer.py` (chunk dedup, query-aware slicing) +
  `cache_aware_chunker.py`.
- **Tool-output compression** — `tool_output_compressor.py` (error-aware: keeps
  failures/stack frames, drops passing-test noise) + `tool_output_filter.py`;
  per-tool budgets + first-appearance (monotonic) normalization in `optimizer.py`.
- **Budget & eviction** — `budget_governor.py` (BudgetGovernor: calibrated/horizon/
  code-density budget math) + `token_aware_truncator.py` + `token_counter.py`;
  space-based folding (`fold_window_fraction`, default 0.25) keeps the prefix stable.
- **Context compression** — `context_compressor.py`, `context_canonicalizer.py`,
  `selective_truncator.py`, `context_aligner.py`.
- **Hierarchical summarization** — `hierarchical_summarizer.py` (cache-stable
  rolling-summary compaction) + `summarize_old_turns.py`.
- **Reversible compression** — `content_store.py` (content-addressed handles +
  model-facing `expand_content(handle)` retrieval; config-gated OFF).
- **Prefix reuse & prediction** — `static_prefix_kv.py`, `cache_registry.py`,
  `hit_prediction_model.py` (XGBoost early-exit), `chunk_fingerprint.py`,
  `delta_encoder.py`.
- **Backend communication** — `backend_client.py`, `backend_capabilities.py`
  (live, device-aware auto-detection of slot pinning, native MTP, tokenizer).
- **Observability** — process-wide `/v1/metrics`, bounded per-request `/v1/debug/requests`
  trace, and per-stage degradation counters with structured reason codes
  (e.g. `code_slicing:parser_unavailable:lang=…:size=…:failed_open`).
- **Async offload** — `async_io_stage.py` (offloads tree-sitter + embedding ranking
  to a thread pool; primary TTFT cost).

## Hard constraints (do not violate)

- Proxy scope = input compaction only; never compress response verbosity.
- Keep cached prefixes byte-stable; never mutate the middle of cached context. The
  dry-run (`benchmark/diag_dryrun_opencode.py --max-breaks`) is the local prefix-stability
  gate for cache-touching changes — but it proves LOCAL prefix stability only, not
  backend KV retention.
- Bounded diagnostics: never put the full session state / optimized prompt in a normal
  response; use bounded scalar headers + `/v1/debug/requests` (opt-in, capped).
- Gated context-rewriting features (`reversible_compression_enabled`,
  `code_slicing_enabled`, `tool_output_dedup_enabled`,
  `volatile_field_neutralization_enabled`) stay OFF by default pending benchmarks.
- Benchmark invariant: never interleave direct and proxified requests within a round.
- Only the new benchmark format is supported (no legacy logs).
- Dashboard charts follow the FT Visual Vocabulary.
- Internal cache hints (attention sinks, pattern markers) are stripped before model input.
- Capability auto-detection drives slot pinning / MTP passthrough / tokenizer; the
  explicit force-on flags are overrides, not defaults.

## Common commands

```bash
bash scripts/run.sh                 # start proxy on :8080
bash scripts/dev.sh                 # install + pytest + ruff + mypy
pytest tests/ -v                    # tests only
ruff check src/ tests/              # lint
mypy src/moeptimizer/               # type-check
python -m moeptimizer --check-config  # validate resolved config
python -m benchmark.diag_dryrun_opencode --persistent-session --turns 30 --max-breaks 7 2>&1  # expected-fold gate; fails on excess/non-fold breaks
python benchmark/benchmark.py --scenario opencode --turns 30 --json > report.json 2> run.log
```

## Where to look for common tasks

- **Add a config flag**: `src/moeptimizer/config.py` (`AppConfig`) → `.env.example` →
  `README.md` config table.
- **Add a pipeline stage**: new module → wire into `optimizer.py` → re-export from
  `__init__.py` → add `tests/test_<module>.py`.
- **Change an endpoint**: `src/moeptimizer/app.py` (`create_app`).
- **Change backend communication**: `src/moeptimizer/backend_client.py` /
  `backend_capabilities.py`.
- **Change benchmark**: `benchmark/benchmark.py` (keep no-legacy / no-interleave
  invariants) and `benchmark/dashboard.html`.
